# Agent pattern inventory: PDF-first reconciliation

**Source/edition:** Imran Ahmad, *30 Agents Every AI Engineer Must Build*, Packt, first published March 2026, ISBN 978-1-80610-901-2 (physical PDF p.3).

**Scope:** The PDF's Table of Contents and developed Chapters 5-16 define the source inventory. Chapters 1-4 supply foundations; Chapter 17 is an epilogue. The official repository is a separately labeled numbering/name comparison. This document supports future independent implementations and does not transplant repository code or claim production readiness.

**Page-locator convention:** Printed numbers below are verified from page text/header/footer; `PDF` means 1-based physical page. Section spans can overlap because a new heading and the preceding section sometimes share a page. Front matter uses verified Roman numerals. A missing section has no invented body span.

**Source analysis; no implementation or runtime validation performed.** Dependencies are explicitly named source examples, alternatives, shared chapter prerequisites, or interface concepts; they are not an install plan or a current verified recommendation. Problem/user and input/output columns are concise interpretations of the cited architecture, not promises of implemented behavior.

## Count and name reconciliation

The [official Packt repository's numbered reference list](https://github.com/PacktPublishing/30-Agents-Every-AI-Engineer-Must-Build#the-30-agents-at-a-glance) contains 30 entries. The PDF also develops 30 named sections, but the two sets differ:

| Reconciliation | Count | Meaning |
| --- | ---: | --- |
| Official numbered references | 30 | Stable reference IDs 01-30 used below |
| Developed PDF sections corresponding to official references | 29 | Includes the explicitly provisional #14 correspondence |
| Official reference without a developed PDF section | 1 | #18 Recommendation |
| Additional named PDF pattern | 1 | Domain-Transforming Integration |
| Developed PDF pattern sections in total | 30 | 29 corresponding sections + one additional section |
| Inventory records, including the source gap | 31 | All 30 official references + the additional PDF section |

- **#14 is a material naming/coverage discrepancy.** The Preface promises security-hardened patterns for prompt-injection defense; the Chapter 9 TOC and body instead develop **Compliance-Driven agents**, centered on policy/code enforcement. Correspondence follows its position as the middle Chapter 9 pattern and related security/compliance topic. Do not silently treat the names or coverage as identical. (Preface, printed p.xxiii; PDF p.24; TOC, printed p.xv; PDF p.16; Ch.9, Compliance-Driven agents, printed pp.255-265; PDF pp.286-296.)
- **#18 is a source gap.** The Preface mentions recommendation agents/hybrid recommenders, and the official reference list includes one. The Chapter 10 TOC/body/summary develop only Conversational and Content Creation. The Preface supplies a synopsis and the conversation section foreshadows recommendation work that never receives a developed heading. Searches for standalone recommendation/recommender agent names found no body section. Its linked brief must preserve the gap rather than invent a book architecture. (Preface, printed p.xxiii; PDF p.24; TOC, printed p.xvi; PDF p.17; Ch.10, Why conversational agents are necessary, printed p.283; PDF p.314; Ch.10 body/summary, printed pp.281-306; PDF pp.312-337.)
- **The extra pattern is developed source material.** Domain-Transforming Integration has its own Chapter 16 heading, architecture, and implementation discussion, followed by a case that composes it with Embodied Intelligence. It is not official item #31. (TOC, printed p.xix; PDF p.20; Ch.16, printed pp.473-490; PDF pp.504-521.)

The exact source headings below retain the PDF's singular/plural and capitalization, with line wrapping normalized. The official alias column records the repository comparison; it does not override the source name.

## Evidence limits and later implementation decisions

- The inventory verifies headings, page boundaries, intended architecture, and representative named dependencies. It does not verify that each code listing is complete, that imports exist today, that credentials/API access are available, or that case-study metrics are reproducible.
- Package versions differ between chapters, and shared chapter prerequisites may serve only one example. Derive a minimal dependency plan separately for each future demo from current official documentation.
- Preserve the source gap for #18. An independently designed recommendation demo could be added later only with explicit labeling that its architecture comes from new sources or original design, rather than this PDF's absent section.
- Use the named PDF sections as learning units, not a mandate to deploy 30 services. Several patterns are composable capabilities; #29 is explicitly a team architecture. A useful demo can show a boundary or control loop without reproducing an entire fictional deployment.
- All named section boundaries and cited dependency pages were readable in extracted text. Some extraction contains embedded index markers or compressed code whitespace; headings and source paraphrases were normalized manually. Figure-only pages and blanks are outside this table's identity claims. The missing Recommendation section is a source inconsistency, not reported as unreadable content.
